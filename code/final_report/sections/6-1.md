**Pipeline.** One engine, `code/flood.py`, serves every script: it caches the basin tables, applies the fixed split, fits scalers and the high-flow level on the training years only and trains with early stopping on the validation years. Scripts 01 to 22, the `check_*.py` checks and the `fetch_*.py` downloaders each answer one question and write `results/*.json` and `figures/*.png`.

**One source of numbers.** The documents are built by code that reads `results/*.json` and nothing else, through a registry that records the file and key behind every value (Appendix C). `results/preds/` holds one forecast file per model and seed ({{num:count_preds_npz}} files) and `results/models/` the saved networks ({{num:count_models_pt}}); the headline sets of script 04 were not saved (re-scorable, not reloadable).

**Interface, API, database, security.** None: an offline research pipeline, no service or demo.

**Error handling.** Engine asserts refuse incomplete records, unmatched date indexes, input gaps, a non-causal network and a validation run without a finite score; `code/test_flood.py` runs the {{num:fair_test_n_checks}} leak checks of Section 4.2 ({{num:fair_test_passed}}); the engine review's defects were all fixed before the experiments (Section 6.3, Table T24).
