**How to reproduce (README.md, Run it).** Install the pins into a fresh Python environment with `pip install -r requirements.txt`. `python code/test_flood.py` runs the fairness checks on made-up data and needs no data. `python code/build_report.py` rebuilds the detailed report from results/ and figures/ alone. `FLOOD_QUICK=1 ./run_all.sh` runs every script in a few minutes with tiny budgets as a smoke test; its output under results/quick and figures/quick means nothing. Running `./run_all.sh` in full retrains every model from the raw data (about {{num:work_hours}} on the laptop) and overwrites results/; the submitted numbers come from the stored runs. The order of run_all.sh is the table of README.md: data audit, fairness checks, baselines, the one-river LSTM, the all-river LSTM, the leave-one-out test, basin maps and satellite fetch, rain timing, flood analysis, satellite inputs, model comparison, day windows, the four experiments of the hand-over week (rain to midnight with ERA5, the rain clock, AORC with the hindsight check, more basins, the GEFS forecast), then learning curves, resampling ranges, the same-misses check, the key figure and the guide figures. One headline number can be checked in seconds from the stored forecasts: in code/, `python -c 'import flood as F; s = F.evaluate(F.load_preds("lstm_wq"), F.thresholds(F.load_data()))["summary"]["l1"]; print(s["nse_median"], s["onset"]["pod"])'` prints the median NSE and the share of onsets warned one day ahead of the LSTM with the river gauge.
